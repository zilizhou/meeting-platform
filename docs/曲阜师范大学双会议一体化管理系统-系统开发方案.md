## 1. 建设目标与范围

### 1.1 建设目标

建设面向全校二级学院统一部署的双会议并行管理平台，将议事规则固化为可执行流程，实现：

1. **双会独立运行**：党委会、党政联席会流程隔离、权限隔离、名单隔离  
2. **数据互通闭环**：党委会前置决议可流转至联席会，禁止相互替代  
3. **制度硬校验**：法定人数、双人联审、前置材料、回避、表决、双签纪要等不可绕过  
4. **督办必达**：决议自动生成任务，执行反馈可追溯、可问责  
5. **巡视可查**：校院两级台账、一键导出巡视材料包  

### 1.2 建设范围

| 范围 | 说明 |
|-----|------|
| 覆盖单位 | 全校二级学院（统一租户/多学院隔离） |
| 会议类型 | 学院党委（党总支）会、党政联席会议 |
| 用户端 | 管理端 Web、移动端 H5/企微（阅件、签到、待办） |
| 校级端 | 组织部/党政办监管看板、模板下发、巡视导出 |
| 不在本期 | 校级党委常委会系统、教代会独立系统（仅做意见材料挂接） |

### 1.3 干系人与角色

| 角色 | 典型岗位 | 系统职责 |
|-----|---------|---------|
| 校级管理员 | 党委组织部、党政办公室 | 全校监管、模板/流程配置、巡视导出 |
| 学院管理员 | 党委秘书、行政办主任 | 会务、议题收集、归档、督办催办 |
| 党委书记 | 学院党委书记 | 党委会审题/主持；联席会联审；纪要会签 |
| 院长 | 学院院长 | 联席会联审/主持；纪要会签 |
| 班子成员 | 副书记、副院长、党委委员 | 提议题、阅件、参会、表决、督办反馈 |
| 列席人员 | 按议题确定 | 阅件、发言；无表决权 |
| 会议秘书 | 办公室会务人员 | 通知、材料、记录、纪要起草 |

## 2. 需求分析摘要

### 2.1 业务需求（制度映射）

| 规则要点 | 系统需求编号 | 实现要点 |
|---------|-------------|---------|
| 二者不可相互替代 | BR-01 | 跨会议合规引擎 + 前置关联强制校验 |
| 半数/三分之二到会 | BR-02 | 签到后实时计算，未达标禁止形成决议 |
| 书记院长协商确定议题 | BR-03 | 双人联审状态机，不一致→暂缓 |
| 一事一报、材料提前送达 | BR-04 | 议题材料清单 + 推送回执 |
| 会前调研/审查/委员会意见 | BR-05 | 按议题类型动态必填材料 |
| 一题一议、禁止随意临时动议 | BR-06 | 议程锁定 + 临时议题双签 |
| 同意/不同意/缓议 + 最后表态 | BR-07 | 讨论意见结构化 + 表态顺序控制 |
| 表决过应到会正式成员半数 | BR-08 | 以应到正式成员为基数自动计票 |
| 缺席意见不计票 | BR-09 | 书面意见可登记，票数字段隔离 |
| 四类决议 | BR-10 | 决议枚举固化 |
| 回避 | BR-11 | 议题级回避名单，禁止表决 |
| 纪要双签生效 | BR-12 | 书记+院长电子签后生效 |
| 督办与问责 | BR-13 | 任务闭环 + 逾期/不力标记 |
| 巡视检查 | BR-14 | 指标看板 + 材料包导出 |

### 2.2 非功能需求

| 类别 | 指标 |
|-----|------|
| 性能 | 常规页面 P95 < 1.5s；会中签到/表决接口 P95 < 500ms；单学院并发 ≥ 50 |
| 可用 | 核心会务时段可用性 ≥ 99.5%；支持会话级断线重连提示 |
| 安全 | 统一身份认证；RBAC+数据权限；全链路操作审计；涉密材料水印与下载审计 |
| 合规 | 关键操作不可物理删除（逻辑删除+审计）；决议链路可完整回溯 |
| 兼容 | Chrome/Edge 近两个大版本；移动端适配企微内置浏览器 |
| 扩展 | 预留人事/财务/科研/学工/档案系统对接接口 |

## 3. 总体架构设计

### 3.1 逻辑架构

```
┌─────────────────────────────────────────────────────────────┐
│                        接入层                                │
│   Web 管理端  │  移动端 H5/企微  │  开放 API（校级系统对接）   │
└─────────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────────┐
│                        网关层                                │
│   统一认证  │  路由  │  限流  │  审计网关  │  文件鉴权下载      │
└─────────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────────┐
│                       业务服务层                              │
│ 组织权限 │ 议题中心 │ 党委会 │ 联席会 │ 合规引擎 │ 会议运行     │
│ 纪要会签 │ 督办中心 │ 档案中心 │ 消息通知 │ 监管报表 │ 巡视导出  │
└─────────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────────┐
│                       领域能力层                              │
│ 工作流引擎 │ 表单/材料引擎 │ 表决引擎 │ 电子签章 │ 导出引擎     │
└─────────────────────────────────────────────────────────────┘
┌─────────────────────────────────────────────────────────────┐
│                       数据与基础设施                          │
│ MySQL │ Redis │ 对象存储 │ 消息队列 │ 日志检索 │ 备份容灾       │
└─────────────────────────────────────────────────────────────┘
```

### 3.2 部署架构（校内私有化）

```
校园网用户 ──► Nginx/网关 ──► 应用集群（无状态）
                              ├─ 业务服务
                              ├─ 工作流服务
                              └─ 文件服务
                    MySQL主从 / Redis / MinIO或校内对象存储
                    定时任务 / 消息队列
```

- 生产建议：应用双实例以上；数据库主从；文件存储独立；定时备份  
- 网络：默认校园网访问；如需外网，走学校 VPN/零信任  

### 3.3 多学院隔离模型

采用 **单应用多租户（按学院隔离）**：

- 所有业务表含 `college_id`  
- 行级数据权限：学院用户仅本院；校级管理员可跨院只读/导出  
- 参会名单、流程配置支持「校级模板 + 学院覆盖」

## 4. 技术选型建议

> 以下为推荐基线，可按学校现有技术栈替换，但模块边界建议保持不变。

| 层级 | 推荐技术 | 说明 |
|-----|---------|------|
| 前端 Web | Vue 3 + TypeScript + Element Plus | 后台表单/流程类系统成熟 |
| 移动端 | uni-app 或 Vue3 H5 | 优先嵌入企微/钉钉 |
| 后端 | Java 17 + Spring Boot 3 | 高校信息化常见栈；或 NestJS/Go 等价实现 |
| 工作流 | Flowable / Camunda 或自研状态机 | 双审、会签、督办适合状态机+少量 BPMN |
| 数据库 | MySQL 8.0 | 事务强、运维成熟 |
| 缓存 | Redis | 会话、签到计数、分布式锁、待办缓存 |
| 文件 | MinIO / 学校统一对象存储 | 材料、纪要、附件 |
| 消息 | RabbitMQ / RocketMQ | 通知、异步导出、督办提醒 |
| 文档导出 | 模板引擎（Word/PDF） | 纪要、巡视材料包 |
| 电子签 | 学校统一签章或本地手写板+签章图片 | 书记院长双签 |
| 认证 | CAS / OAuth2 / 统一身份 | 对接学校统一认证 |
| 监控 | Prometheus + Loki/ELK | 性能与审计检索 |

**关键设计选择：联席会/党委会核心流程建议「领域状态机 + 规则引擎」为主，BPM 为辅**，避免把法定人数、计票等硬规则淹没在通用流程配置里。

## 5. 功能模块开发设计

### 5.1 模块划分与依赖

```
组织权限 ──► 议题中心 ──► 党委会子系统
                │              │
                ├──────────────┼──► 合规引擎
                │              │
                └────────► 联席会子系统 ──► 会议运行（签到/讨论/表决）
                                              │
                                         纪要会签 ──► 督办中心 ──► 档案中心
                                              │
                                         监管报表 / 巡视导出
```

### 5.2 模块1：组织与权限

**开发要点**

1. 组织：学校 → 学院 → 班子职务 → 人员  
2. 角色权限：RBAC（菜单/按钮/接口）+ 数据权限（学院/本人/分管）  
3. 双会名单：`party_committee_roster`、`joint_meeting_roster` 分表维护  
4. 法定人数配置：普通召开阈值、重大事项阈值（默认 1/2、2/3，校级锁定）  
5. 代理人/请假：会前请假登记，不影响应到基数计算规则  

**接口示例**

- `GET /api/colleges/{id}/rosters?meetingType=`  
- `PUT /api/colleges/{id}/rosters`  
- `GET /api/auth/me/permissions`  

### 5.3 模块2：议题中心

**统一议题模型，按会议类型分流**

| 字段 | 说明 |
|-----|------|
| meeting_type | PARTY / JOINT |
| category_code | 对应规则分类字典 |
| need_party_precheck | 是否需党委会前置 |
| related_party_resolution_id | 关联党委会决议 |
| material_checklist | 动态材料清单及完成状态 |
| joint_review_status | 书记/院长联审状态 |
| avoid_user_ids | 回避人员 |
| is_major | 是否重大事项（影响法定人数阈值） |

**材料引擎**

按 `category_code` 加载必填项模板，例如：

- 教学科研/人才/学科类 → 相关委员会意见  
- 师生切身利益类 → 教代会或征求意见材料  
- 大额资金类 → 预算说明、合规审查  
- 党委转办类 → 必须关联党委会决议  

### 5.4 模块3：党委会子系统

状态机建议：

```
草稿 → 待书记审 → 已排期 → 会中 → 待纪要 → 已生效 → 已归档
              ↘ 退回
已生效后可派生：党建督办 / 转联席会议题
```

开发重点：

1. 党建类议题白名单校验  
2. 「需会后提交联席会」自动打标与流转单生成  
3. 档案子类：党员发展、意识形态、党风廉政、民主生活会、中心组学习等  

### 5.5 模块4：党政联席会子系统

状态机建议：

```
议题草稿 → 材料校验 → 双人联审 → 已入议程 → 会中 → 已决议
                ↘ 材料退回   ↘ 暂缓上会
已决议 → 纪要双签生效 → 督办中 → 办结归档
```

开发重点（对应规则）：

1. 双人联审：书记、院长均同意才可入议程；任一方不同意→暂缓  
2. 主持人：按议题指定书记或院长  
3. 临时动议：单独审批流，须书记+院长同意  
4. 紧急临机处置：会后补确认流程（第十三条）  

### 5.6 模块5：会议运行（签到 / 讨论 / 表决）

**签到服务**

- 计算 `should_attend`（正式成员应到）、`actual_attend`  
- 校验：`actual/should >= threshold`  
- 未达标：允许继续讨论记录，但 `can_resolve=false`  

**讨论服务**

- 结构化意见：AGREE / DISAGREE / DEFER + 理由  
- 表态顺序：可配置「书记、院长最后表态」闸门  

**表决引擎（核心）**

```
通过条件：approve_votes > should_attend_formal / 2
计数范围：仅正式成员且未回避且已签到（或按学校确认的计票口径配置）
缺席书面意见：写入 opinion 表，vote_counted=false
列席：禁止写入 vote
多议题：强制逐项表决，禁止批量一键通过
```

表决方式：ORAL / HAND / BALLOT（无记名时仅存汇总，不存个人选项明文可配置）。

### 5.7 模块6：合规引擎

独立领域服务，供议题提交、入议程、形成决议前调用。

| 规则码 | 触发点 | 失败策略 |
|-------|-------|---------|
| RULE_PRECHECK_REQUIRED | 联席会上会 | 阻断 |
| RULE_DUAL_REVIEW | 入议程 | 阻断 |
| RULE_QUORUM | 形成决议 | 阻断 |
| RULE_AVOIDANCE | 表决 | 剔除并告警 |
| RULE_NO_SUBSTITUTE | 议题创建/保存 | 预警或阻断（按事项标签） |
| RULE_TEMP_MOTION | 临时议题 | 阻断至双签 |
| RULE_MINUTE_SIGN | 纪要生效 | 阻断 |

所有规则执行写 `compliance_check_log`，供巡视抽查。

### 5.8 模块7：纪要与电子签

1. 模板：校级下发 Word/富文本模板，学院可微调非关键字段  
2. 内容：自动带入议题、讨论摘要、表决结果、决议类型、责任人  
3. 生效：书记签 + 院长签 → `effective_at`  
4. 变更：生效后仅允许勘误并留痕，不覆盖原件（版本+1）  

### 5.9 模块8：督办中心

状态：`PENDING → ACCEPTED → IN_PROGRESS → FEEDBACK → DONE / OVERDUE / ADJUST_REQUEST`

1. 决议生效自动拆任务  
2. 办公室催办、分管反馈、附件证明  
3. 重大调整/复议：生成回流议题，禁止直接改决议  
4. 问责标记：执行不力、擅自变更等枚举，供考核导出  

### 5.10 模块9：档案 / 公开 / 保密

1. 会议全宗：通知、材料、签到、表决、纪要、督办一次性绑定 `meeting_id`  
2. 公开：可公开决议按范围发布；默认未公开  
3. 涉密：密级字段、水印、下载审计、会后收回确认单  
4. 检索：按学年、分类、三重一大、关键词  

### 5.11 模块10：校级监管与巡视导出

指标示例：

- 双审完成率、前置把关率、法定人数达标率、纪要双签及时率、督办按期办结率、临时动议占比  

导出包结构：

```
巡视材料包/
  01-制度与配置/
  02-会议台账.xlsx
  03-抽样会议全宗/
  04-督办台账.xlsx
  05-合规校验日志.xlsx
  06-整改与问责记录/
```

### 5.12 模块11：消息通知

事件驱动：议题待审、材料待阅、会前提醒、签到、会签、督办逾期、校级预警。  
通道：站内信 + 企微/钉钉 +（可选）短信。

## 7. 接口与集成设计

### 7.1 API 风格

- RESTful + JSON  
- 统一响应：`{ code, message, data, traceId }`  
- 幂等：表决提交、会签提交使用 `Idempotency-Key`  
- 分页、排序、学院过滤统一中间件处理  

### 7.2 关键 API 分组

| 联席会 | `/api/joint-meetings/**` |

|-----|---------|------|
| 统一身份认证 | CAS/OAuth2 | 登录、组织人员同步 |
| 企微/钉钉 | 应用消息 API | 待办与提醒 |
| 电子签章 | SDK/API | 纪要双签 |
| 人事/科研/财务 | 只读查询或附件引用 | 辅助材料（二期后） |
| 档案系统 | 归档推送 | 全宗移交（三期） |

## 8. 安全设计

1. **认证授权**：统一认证 + JWT/会话；接口级鉴权；按钮级权限码  
2. **数据隔离**：强制 `college_id` 过滤器，防越权  
3. **防篡改**：决议、表决、纪要生效后只追加版本；关键字段变更写审计  
4. **文件安全**：上传类型白名单、病毒扫描（如有）、临时下载链、水印  
5. **保密**：涉密议题默认缩小可见范围；禁止外发下载可配置  
6. **会中安全**：表决接口短时限流、防重复提交、操作者二次确认  
7. **等保与日志**：登录、导出、授权变更、决议生效等安全事件入库可检索

## 10. 关键业务时序（开发验收用）

### 10.1 联席会议题上会

```
申报人提交议题
 → 材料引擎校验
 → 书记联审 + 院长联审
 → 通过则入会议议程 / 不通过则暂缓
 → 办公室推送材料并回收回执
 → 开会签到并校验法定人数
 → 一题一议讨论（书记院长最后表态）
 → 表决计票
 → 生成决议
 → 纪要双签生效
 → 生成督办
 → 归档
```

### 10.2 党委会转联席会

```
党委会决议生效且标记需转办
 → 生成 transfer_link
 → 自动创建联席会议题草稿（只读关联原决议）
 → 联席会联审与上会
 → 落实类决议与督办
```

## 11. 实施计划

### 11.1 分期交付

| 阶段 | 周期 | 交付内容 | 验收重点 |
|-----|------|---------|---------|
| 一期 | 8–10 周 | 组织权限、联席会全流程、会中签到表决、纪要双签、督办、基础档案、消息 | 规则第七–十七条可演示闭环 |
| 二期 | 6–8 周 | 党委会子系统、跨会流转、合规引擎强化、移动端待办、校级基础报表 | 不可替代校验、转办链路 |
| 三期 | 4–6 周 | 巡视导出包、全校监管看板、系统对接、性能与安全加固、全校推广 | 巡视材料一键导出、多学院稳定运行 |

### 11.2 里程碑

1. M1：需求确认 + 原型评审  
2. M2：数据库与合规规则评审  
3. M3：一期 UAT（试点学院）  
4. M4：二期联调与制度部门验收  
5. M5：全校培训上线  

### 11.3 试点策略

先选 2–3 个学院（文/理/工各一）试运行一个学期会期，再全校铺开；校级组织部、党政办同步试用监管端。

## 12. 测试方案

| 测试类型 | 内容 |
|---------|------|
| 功能测试 | 双会全流程、四类决议、督办回流 |
| 规则测试 | 法定人数、计票、回避、双审、前置关联等用例集（必须自动化） |
| 权限测试 | 越权访问、列席无表决权、学院隔离 |
| 会中压测 | 签到、表决并发 |
| 安全测试 | 附件、导出、审计完整性 |
| UAT | 学院秘书实操 + 组织部抽查台账 |

**规则测试用例（示例必过）**

1. 到会不足半数，无法形成决议  
2. 重大事项未达三分之二，无法形成决议  
3. 书记同意院长不同意，议题暂缓  
4. 缺席书面同意不计入赞成票  
5. 列席人员调用表决接口返回 403  
6. 需前置议题无党委会决议无法入联席会议程  
7. 纪要单签不能生效  
8. 督办重大调整必须回流新议题

## 15. 风险与对策

## 16. 验收标准（总括）

1. 能按曲师大委字〔2021〕20号完成联席会从申报到督办归档全流程  
2. 法定人数、双审、计票、双签、回避等硬规则 100% 有自动校验与日志  
3. 党委会与联席会数据隔离且支持转办关联，替代风险可预警  
4. 校级可查看全校台账并导出巡视材料包  
5. 试点学院连续完成不少于 4 次正式会议线上闭环  
6. 通过安全与权限测试，无高危越权/数据串院问题
