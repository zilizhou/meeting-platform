# 曲阜师范大学二级学院党委会、党政联席会议一体化管理系统方案

> 制度依据：曲师大委字〔2021〕20号《学院党政联席会议议事规则》（2021年3月19日印发）  
> 配套依据：《学院党委会议议事规则》（党委会专议党建类事项）

---

## 一、系统建设依据（曲师大制度底座）

### 1. 校级文件

- 《学院党政联席会议议事规则》（曲师大委字〔2021〕20号）
- 《学院党委会议议事规则》

明确：**党委会前置把关、党政联席会决策、二者不可相互替代**的运行机制（规则第二条）。

### 2. 核心权责区分（严格对应规则条文）

| 会议类型 | 权责边界 | 制度出处 |
|---------|---------|---------|
| **学院党委（党总支）会** | 专议党的建设，包括干部选拔任用、基层党组织和党员队伍建设等；涉及办学方向、教师队伍建设、师生员工切身利益等重大事项，须**先行把关**，再提交党政联席会议决定 | 规则第二条、第五条 |
| **党政联席会议** | 讨论和决定学院工作中的重要事项，保证其对单位重要事项的决定权；**不能用党政联席会议代替党委（党总支）会会议** | 规则第二条、第四条 |

**参会人员（规则第七条）**

- 正式成员：学院党政领导班子成员（党委正副书记、正副院长）
- 列席人员：由党政主要负责人协商确定；**有发言权，没有表决权**

### 3. 硬性流程约束（规则第三章、第四章、第二十一条）

全流程线上闭环，覆盖：

| 约束点 | 规则要求 | 系统落地 |
|-------|---------|---------|
| 召开频次 | 一般每两周一次，重要情况可随时召开 | 会期日历、临时会议申请 |
| 到会人数 | 半数以上方可召开；重大事项决策须三分之二以上到会 | 签到自动校验法定人数 |
| 议题确定 | 班子成员提出，书记与院长协商确定；意见不一致暂缓上会 | 双人联审、暂缓锁定 |
| 会前材料 | 一事一报，材料提前送达参会人员 | 材料包推送、阅件回执 |
| 调查研究 | 重要事项会前调研、合法合规审查、风险评估；涉教学科研等须听取相关委员会意见；涉师生利益须听取教代会等意见 | 前置材料清单强制校验 |
| 临时动议 | 无特殊情况或未经书记、院长同意，一般不临时动议 | 临时议题双签审批 |
| 表决规则 | 口头/举手/投票；赞成票超过应到会正式成员半数为通过；未到会意见不得计入票数 | 表决留痕、票数自动统计 |
| 决议类型 | 批准/通过；原则批准；暂不形成决议；不予批准 | 决议枚举与督办分流 |
| 回避制度 | 涉及本人或亲属等影响公正决策的须回避 | 利益关联申报与强制回避 |
| 纪要生效 | 会议记录、纪要由书记、院长签字后生效 | 双人电子会签 |
| 督办落实 | 分管负责人组织实施，党政办公室督促检查，执行情况汇报 | 督办任务、反馈、问责标记 |
| 巡视留痕 | 学校结合巡察或专项检查检查执行情况 | 校级台账、巡视导出包 |

## 二、系统总体定位

面向全校二级学院（文、理、工、计算机/网安、教育、外语、经济、法学院等）**统一部署**的双会议并行一体化线上管理平台。

**建设目标：** 议题申报 → 会前筹备 → 线上签到 → 会议记录 → 决议下达 → 督办跟踪 → 档案归档 → 巡视自查 → 校级监管，全流程线上闭环。

**解决痛点：**

1. 线下纸质台账散乱，调阅困难  
2. 决议督办无跟踪、无反馈  
3. 党委会与党政联席会边界不清、相互替代风险  
4. 到会人数、表决程序、回避等硬性要求难核验  
5. 巡视整改、专项检查材料准备成本高、留痕不足  

**设计原则：**

- **双会议独立流程 + 数据互通**：流程隔离、权限隔离，重大事项可从党委会「转联席会」流转  
- **制度即流程**：规则条文固化为系统校验规则，不可绕过  
- **校院两级管控**：学院自治运行，校级可监管、可导出、可问责溯源

## 三、核心功能模块（双会议独立流程 + 数据互通）

### 模块1：组织与权限管理（校级—学院分级管控）

#### 1.1 校级管理员（党委组织部、党政办公室）

- 查看全校所有学院会议台账、决议与督办状态  
- 导出巡视/专项检查汇总报表  
- 下发制度模板、议事规则版本、纪要模板  
- 配置流程节点、法定人数阈值、议题分类字典  
- 对违规程序（未达法定人数仍形成决议等）进行预警与约谈标记  

#### 1.2 学院管理员（党委秘书 / 行政办主任）

- 维护本院参会人员、列席人员库  
- 议题收集、材料分发、会务组织  
- 纪要编发、归档、督办更新  

#### 1.3 角色分层与权限隔离

| 角色 | 主要权限 |
|-----|---------|
| 党委书记 | 党委会主持/审题；联席会议题联审；纪要会签；最后表态顺序控制 |
| 院长 | 联席会议题联审/主持；纪要会签；最后表态顺序控制 |
| 党委委员 | 党委会参会、阅件、表决 |
| 副院长 | 联席会参会、阅件、表决；分管议题申报与督办反馈 |
| 列席人员 | 按议题授权阅件、发言登记；**无表决权** |
| 会议秘书 | 会务全流程操作；记录起草；无表决权 |

#### 1.4 名单与法定人数

- 党委会、党政联席会参会名单**分开维护**  
- 联席会自动校验（规则第七条）：  
  - 普通召开：正式成员到会 ≥ 1/2  
  - 重大事项决策：正式成员到会 ≥ 2/3  
- 分管负责人无特殊情况必须到会；请假须会前向主持人报备并留痕

### 模块2：党委会会议全流程子系统

#### 2.1 议题申报

仅限党建类及规则第五条所列事项，例如：

- 贯彻落实学校党委关于加强学院党的领导和党的建设的具体措施  
- 师生思想政治工作、教风学风和师德师风建设  
- 意识形态、统一战线和安全稳定  
- 党风廉政建设和巡视巡察整改  
- 干部选拔任用、基层党组织和党员队伍建设  
- 党委（党总支）提名的所属机构、单位负责人建议任免人选（会后提交联席会审议任免）  

申报人须上传：调研材料、前置征求意见表、相关依据文件。

#### 2.2 双审与流转标记

- 党委书记初审议题  
- 涉及办学方向、教师队伍建设、师生切身利益等重大事项，系统自动标记：**「需会后提交党政联席会」**  
- 形成「党委会决议 → 联席会落实/审议」的跨会议流转单，防止用联席会替代党委会  

#### 2.3 会前筹备

- 自动生成会议通知、线上回执签到  
- 材料包批量推送委员  
- 支持会前阅件批注  

#### 2.4 会议召开

- 线上签到 + 法定人数校验  
- 曲师大标准党委会议纪要模板  
- 表决记录（举手/无记名投票留痕）  
- 列席人员登记（发言权/无表决权）  

#### 2.5 会后闭环

- 纪要线上会签  
- 决议自动生成督办任务，区分：  
  - **党建专项任务**（本院党委系统内闭环）  
  - **转党政联席会审议/落实事项**（自动生成联席会议题草稿）  

#### 2.6 档案分类归档

独立归档目录：

- 党员发展台账  
- 意识形态研判记录  
- 党风廉政专题会议  
- 民主生活会  
- 中心组学习  
- 巡视巡察整改专题

### 模块3：党政联席会议全流程子系统（办学决策主模块）

#### 3.1 议题分类（对应规则第四条议事决策范围）

系统按规则原文八大类建档，便于巡视对照；界面可映射为业务标签：

| 规则分类 | 系统业务标签（便于申报） | 典型事项 |
|---------|------------------------|---------|
| （一）改革发展稳定 | 改革发展规划类 / 经费资产类 / 安全稳定类 | 发展规划、学科专业规划、年度计划、制度修订；机构设置调整；预算决算、大额资金、大额捐赠；大型设备与大宗采购、基建修缮；办学资源配置与资产处置；服务地方；行政审批与后勤重要事项；安全稳定与突发事件 |
| （二）教师队伍建设 | 人事师资类 | 引进培养、团队建设；聘用调动晋升考核职称薪酬；人才计划推荐；违规违纪惩处 |
| （三）学生培养 | 学生工作类 / 教学类 | 学科专业设置调整、培养方案；课程建设、教学管理、教材；学籍、招生毕业就业奖惩、困难帮扶、导师遴选 |
| （四）科研 | 教学科研类 | 平台团队、项目经费、成果转化与奖励 |
| （五）交流合作 | 组织治理类 / 其他 | 国（境）内外教学科研学术交流合作 |
| （六）委员会人选 | 组织治理类 | 学术/教学/教授/学位评定分委员会等组成人员与负责人选任 |
| （七）表彰奖励 | 人事师资类 / 学生工作类 | 学院表彰奖励及上级人选推荐 |
| （八）其他 | 其他「三重一大」事项 | 其他需联席会讨论决定的事项 |

**另设「党委转办落实类」**（规则第五条）：党委会已决议、提交联席会成员共同研究落实的事项，与第四条行政决策类议题分轨管理。

#### 3.2 议题申报与联审（规则第八条、第十条）

1. 党政领导班子成员提出议题（一事一报）  
2. **党委书记、院长协商确定**上会议题；意见不一致 → 系统锁定为「暂缓上会」  
3. 重要议题会前互相沟通记录留痕；个别酝酿情况可登记  
4. 材料提前报送学院党政办公室，办公室推送至参会人员并回收阅件回执  

#### 3.3 会前强制性前置条件（规则第九条）

按议题类型自动生成材料清单，未齐备不得提交联审通过：

- 调研报告 / 情况说明  
- 合法合规性审查意见（视情况）  
- 风险评估材料（视情况）  
- 学术委员会、教学委员会、教授委员会、学位评定分委员会意见（涉教学科研、人才引进、学科建设）  
- 教职工代表大会或其他方式征求意见情况（涉师生员工切身利益）  
- 若属党委会前置事项：须关联党委会决议文号/流转单  

#### 3.4 会前筹备

- 会期建议：默认按「每两周一次」生成排期，支持临时加会（须书记、院长协商同意）  
- 主持人指定：按议题内容由书记或院长主持（规则第六条）  
- 会议通知、回执、材料包、会前阅件批注  
- 列席人员由党政主要负责人协商确定并授权阅件范围  

#### 3.5 会议召开（规则第七、十一、十二、十三、十五、十六条）

| 功能点 | 规则落地 |
|-------|---------|
| 签到与法定人数 | 半数/三分之二自动校验；未达标禁止进入「形成决议」状态 |
| 议程控制 | 按既定议程一题一议；临时动议须书记、院长同意 |
| 汇报与讨论 | 提出人汇报，可指定补充发言；讨论意见登记 |
| 表态顺序 | 支持书记、院长**最后表态**的流程控制 |
| 意见类型 | 同意 / 不同意 / 缓议，并说明理由 |
| 分歧处理 | 重要问题较大分歧 → 标记「暂缓决定」 |
| 表决方式 | 口头 / 举手 / 投票；赞成票 > 应到会正式成员半数为通过 |
| 缺席意见 | 可会前书面表达，**不得计入票数** |
| 逐项表决 | 多事项必须逐项表决、分别留痕 |
| 回避 | 本人/亲属等情形强制回避，不参与该议题表决 |
| 紧急临机处置 | 事后补报联席会确认（规则第十三条第二款） |
| 列席 | 发言登记，无表决权 |

#### 3.6 决议类型与纪要（规则第十四、十六条）

决议枚举（系统固化）：

1. **批准或通过**  
2. **原则批准或原则通过**（按要求修改后实施或发布）  
3. **暂不形成决议**（责成相关负责人/单位另行提出意见再研究）  
4. **不予批准或不予通过**  

纪要要求：

- 完整记录决策过程（规则第二十一条）  
- 书记、院长双人签字（电子会签）后生效  
- 适合公开的按规定公开；涉密内容保密管理，涉密材料会后收回登记  
- 记录、纪要及材料及时存档  

#### 3.7 会后督办与监督（规则第十七至二十条）

1. 决议自动生成督办任务，指定分管负责人或相关单位  
2. 党政办公室负责传达、督促检查、协调落实  
3. 执行情况定期向联席会汇报；支持「执行不力」问责标记  
4. 执行中需重大调整 → 必须重新上会；需要复议 → 按第八条重新提交议题  
5. 个人无权擅自改变集体决定；保留意见可向上级报告，但执行服从集体决议  
6. 必要时向学校汇报；非涉密事项向教职工、学生通报  
7. 形成校内巡察/专项检查可导出的执行台账  

#### 3.8 档案归档

按学年/学期、议题分类、决议类型、督办状态多维归档；支持「三重一大」专项检索包。

### 模块4：跨会议协同与「不可替代」校验引擎

本模块是制度合规的核心，防止程序空转。

1. **前置把关校验**：标记为「须党委会先行把关」的联席会议题，无关联党委会决议则禁止上会  
2. **转办流转**：党委会「转联席会」事项自动生成联席会议题，保留原决议链路  
3. **替代风险预警**：同一事项仅在联席会决策、从未经党委会的，按事项标签触发合规预警  
4. **双会台账对照**：同一主题在两会中的审议时间、结论、督办状态一屏对照  

---

### 模块5：决议督办与执行反馈

1. 任务分解：责任人、完成时限、交付物、反馈周期  
2. 状态机：待接收 → 推进中 → 已反馈 → 已办结 / 逾期 / 申请调整  
3. 逾期自动提醒书记、院长、办公室  
4. 重大调整、复议走正式议题回流，禁止线下口头变更  
5. 督办报表纳入干部考核、任免参考数据源（呼应规则第二十条）  

---

### 模块6：档案、公开与保密

1. 电子档案：通知、材料、签到、讨论要点、表决、纪要、督办全链路绑定会议ID  
2. 公开管理：可公开决议按范围推送；未公布决定默认保密  
3. 涉密材料：权限水印、会后收回确认、下载审计  
4. 保管期限与移交：按学校档案管理规定配置  

---

### 模块7：巡视自查与校级监管

1. 学院端：议事规则执行自查清单（到会率、双审率、前置把关率、督办办结率、纪要双签率等）  
2. 校级端：全校对比看板、异常学院下钻、约谈/限期整改工单  
3. 一键导出「巡视材料包」：制度文本、会议台账、抽样会议全宗、督办台账、整改闭环  

---

### 模块8：消息通知与移动端

1. 会议通知、材料更新、签到提醒、会签待办、督办逾期多通道提醒（企微/钉钉/短信/站内）  
2. 移动端支持：阅件、回执、签到、待办处理（表决等敏感操作可限制为内网/指定终端）

## 四、关键业务流程（端到端）

### 4.1 党政联席会议标准流程

```
议题提出（班子成员）
    → 材料齐备校验（调研/审查/委员会意见/教代会意见等）
    → 书记与院长协商确定（不一致则暂缓）
    → 办公室分发材料、回收阅件回执
    → 召开（法定人数校验）
    → 一题一议、充分讨论、书记院长最后表态
    → 表决（过应到会正式成员半数）
    → 形成四类决议之一
    → 纪要双签生效
    → 督办下达与反馈
    → 归档 / 公开或保密
    → 校级可监管、可巡视导出
```

### 4.2 党委会 → 联席会协同流程

```
党建/前置类议题党委会审议
    → 形成决议
    → 系统标记「提交联席会审议/落实」
    → 自动生成联席会议题（关联原决议）
    → 联席会按程序研究落实或作出任免等决定
    → 督办闭环
```

---

## 五、关键数据对象（便于研发落地）

| 对象 | 关键字段 |
|-----|---------|
| 会议 | 类型（党委会/联席会）、学院、期次、时间、主持人、应到/实到、是否重大事项、状态 |
| 议题 | 分类、提出人、是否需党委会前置、关联决议、材料清单完成度、联审结果、回避人 |
| 参会 | 角色、正式/列席、签到、请假、表决权 |
| 讨论与表决 | 发言记录、同意/不同意/缓议、表决方式、赞成票、应到基数、是否通过 |
| 决议 | 四类结果、责任人、是否公开、保密级别 |
| 纪要 | 正文、双签状态、生效时间 |
| 督办 | 任务、时限、反馈、逾期、调整/复议回流 |
| 审计日志 | 操作者、时间、对象、前后值（防篡改） |

## 六、非功能要求

1. **合规优先**：法定人数、双审、前置把关、双签、回避等为硬校验，不可配置关闭（校级可审计）  
2. **安全保密**：分级授权、操作审计、涉密隔离；符合学校信息系统安全要求  
3. **高可用**：会中签到、表决、记录等关键时段稳定可用  
4. **可追溯**：任何决议可回溯至材料、讨论、票决、签字全链路  
5. **可扩展**：预留与人事、财务、科研、学工、档案等校级系统的数据接口  

---

## 七、实施步骤建议

| 阶段 | 内容 | 周期建议 |
|-----|------|---------|
| 一期 | 组织权限 + 联席会全流程 + 督办 + 归档 | 试点 2–3 个学院 |
| 二期 | 党委会子系统 + 跨会议流转与合规引擎 | 扩大至半数学院 |
| 三期 | 校级监管看板 + 巡视导出 + 移动端深化 + 系统对接 | 全校推广 |

---

## 八、预期成效

1. **程序合规**：党委会与联席会边界清晰，前置把关、法定人数、表决、双签可核验  
2. **决策留痕**：一事一档，满足巡视巡察、专项检查调阅  
3. **决议必办**：督办闭环，执行不力可追溯问责  
4. **减负增效**：会务标准化，秘书从「找材料」转向「管流程」  
5. **校院贯通**：学院规范运行，学校可监管、可考核、可问责

## 九、附则说明

1. 各学院可在本系统流程框架下配置本院议事决策具体规定，但不得低于校级规则刚性条款；具体规定须经学校党委审核同意后启用（规则第二十二条）。  
2. 本方案涉及党政联席会议部分的解释口径，以党委组织部解释为准（规则第二十三条）。  
3. 党委会子系统的细则字段，待《学院党委会议议事规则》文本一并纳入后做字段级对齐补丁。
