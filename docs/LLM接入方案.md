# 双会议系统 · LLM（大模型）接入方案

| 属性 | 内容 |
|------|------|
| 适用系统 | 曲师大二级学院党委会 / 党政联席会一体化管理系统 |
| 版本 | V0.1（讨论稿） |
| 原则 | **辅助不替代**：AI 只做起草、摘要、提示；审题、表决、签署、硬规则校验仍由人与合规引擎完成 |

---

## 1. 目标

在不削弱制度刚性的前提下，用 LLM 压缩四类高耗时工作：

1. **写**：议题说明、纪要、催办与转办表述  
2. **读**：长材料会前阅件、审题前快速把握要点  
3. **查**：议事规则与本院惯例问答  
4. **催**：督办逾期风险与催办文案  

**明确不做**：自动同意/退回、自动形成决议、自动签署纪要、用模型替代计票与法定人数。

---

## 2. 加在哪里（按流程）

| 环节 | 主要用户 | AI 能力 | 效率收益 | 风险 |
|------|----------|---------|----------|------|
| 议题申报 | 秘书 / 委员 / 副院长 | 分类推荐、材料清单提示、正文润色 | 少返工、一次交齐材料 | 低 |
| 材料阅件 | 班子成员 | 长材料一页摘要、缺项/风险点高亮 | 会前阅读时间大幅缩短 | 中（摘要偏差） |
| 审题（书记 / 双审） | 书记 / 院长 | 审题简报：制度要点、前置是否齐、同类历史 | 审题更快、漏检更少 | 中（不可代审） |
| 会中记录 | 会议秘书 | 讨论结构化、表决叙述、纪要初稿 | 纪要从小时级到分钟级 | 中（须人工改签） |
| 转联席 / 决议 | 书记 / 秘书 | 党委决议 → 联席落实要点拆解 | 转办更规范 | 低 |
| 督办闭环 | 办公室 / 责任人 | 催办话术、逾期风险、反馈质量检查 | 催办更准 | 低 |
| 档案 / 巡视 | 校级 / 学院管理员 | 全宗说明草稿、巡视包导读 | 迎检提速 | 低 |

### 党委会 vs 联席会差异

- **党委会**：审题简报只面向书记；纪要草稿生成后仍 **仅书记签署生效**。  
- **联席会**：审题简报可分「书记侧 / 院长侧」关注点；纪要草稿后仍 **双签生效**。  
- **转联席**：党委决议生效后，AI 可生成联席会议题草案与材料要点，由人确认后创建联席议题。

## 3. 一期优先（建议 4–6 周）

只做「提效最明显、不碰决策权」的三件事：

### 3.1 材料智能摘要（挂：议题详情 / 阅件）

- 输入：已上传材料文本（PDF/Word 解析）+ 议题元数据  
- 输出：一页纸——背景、诉求、关键数字/人事影响、缺项、规则相关风险  
- 交互：只读辅读；标注「AI 生成，以原文为准」；可选要求勾选「已阅原文」再审题  

### 3.2 纪要初稿（挂：会议详情 · 纪要编辑）

- 输入：会议基本信息、签到、讨论意见、表决、决议文  
- 输出：结构化纪要草稿 → 写入「建议稿」→ 秘书「采纳到正文」后走签署  
- **禁止** AI 调用签署接口  

### 3.3 议事规则问答（挂：工作台 / 全局入口）

- 知识库：〔2021〕20 号议事规则、本院补充规定、系统内置 FAQ  
- 要求：回答带条文出处；低置信度时提示咨询组织部 / 学院办公室

## 5. 技术落点（与现有架构对齐）

```
Vue 业务端 / 系统管理端
        │
        ▼
NestJS  ── AiModule（/api/ai/*）── Provider（校内私有化 / OpenAI 兼容）
        │                         │
        │                         ├─ Prompt 版本管理
        │                         ├─ RAG（规则与模板）
        │                         └─ 脱敏 / 配额 / 超时
        ▼
Prisma  AiGeneration（审计：谁、资源、输入摘要、输出、是否采纳）
        Compliance / Topics / Meetings 状态机  ←── AI 不得直接改终态
```

### API（已落地 + 示意）

| 方法 | 路径 | 作用 |
|------|------|------|
| GET/POST | `/api/ai/topics/:id/material-summary` | 材料摘要 |
| GET/POST | `/api/ai/meetings/:id/minutes-draft` | 纪要初稿 |
| GET/POST | `/api/ai/rules/topics`、`/api/ai/rules/ask` | 规则问答 |
| POST | `/api/ai/assist/create` | 申报辅助（分类/材料/标记建议） |
| GET/POST | `/api/ai/topics/:id/review-brief` | 审题简报（辅读，不可代审） |

### 前端形态

- **草稿箱**：生成 → 可编辑建议区 → 「采纳」写入正式字段（纪要、催办、转办说明）  
- **只读辅读**：摘要/简报不可当作审批意见  

---

## 6. 红线

1. AI 不得自动「同意审题 / 形成决议 / 签署纪要 / 办结督办」。  
2. 涉密议题默认关闭外发模型；支持学院级「AI 辅读」开关。  
3. 每次生成写审计（操作者、资源、提示词版本、采纳状态）。  
4. 界面固定提示：「AI 辅助生成，须人工核对，以制度与原文为准」。  
5. **合规引擎结论优先于 AI**；冲突时只展示规则引擎结果。

## 7. 效果度量（上线后）

| 指标 | 说明 |
|------|------|
| 生成次数 / 采纳率 | 是否真的被用 |
| 审题平均时长 | 摘要是否缩短决策准备 |
| 散会 → 纪要生效时长 | 纪要草稿是否提速 |
| 因材料缺项退回率 | 申报辅助是否减少返工 |
| AI 相关投诉 / 纠错单 | 质量与信任 |

## 9. 不建议优先做的

自动表决建议、自动双审通过、用 AI 替代法定人数/计票、无人审校的对外公开稿。  
这些既触及决策权，也难以通过巡视与制度审计。
