# 曲阜师范大学二级学院双会议一体化管理系统

党委会 / 党政联席会议一体化管理平台（一期工程骨架）。支持手机、平板、电脑多终端自适应。

## 技术栈

- 后端：NestJS + Prisma + SQLite（本地默认）/ MySQL（生产可选）+ JWT
- 前端：Vue 3 + Vite + Element Plus + Pinia
- 一期主链路：议题申报 → 双审 → 开会签到 → 表决 → 纪要双签 → 督办

## 快速启动

### 1. 初始化数据库（首次）

```bash
cd backend
pnpm install
pnpm exec prisma migrate dev --name init
pnpm prisma:seed
```

### 2. 启动后端

```bash
cd backend
pnpm dev
```

- API: http://localhost:3000/api
- Swagger: http://localhost:3000/api/docs

### 3. 启动前端（业务端）

```bash
cd frontend
pnpm install
pnpm dev
```

- 业务端: http://localhost:5173

### 4. 启动系统管理端（独立端口）

```bash
cd frontend
pnpm dev:system
```

- 系统管理端: http://localhost:5174（仅 `admin` 等校级账号）
- 与业务端分离：主数据维护在此端；报表/预警/巡视导出仍在业务端「校级监管」

## 建议演示路径

1. 用 `office` 登录 → 议题管理 → 申报议题（自动进入详情）→ **上传本地材料** → 提交双审  
2. 分别用 `secretary`、`dean` 登录，在议题详情点「同意」  
3. 用 `office` 创建联席会议并勾选已通过议题  
4. 进入会议 → 一键全员签到 → 代录全员赞成 → 形成通过决议  
5. 保存纪要后，用 `secretary`、`dean` 分别签署  
6. 在「决议督办」查看自动生成的任务；可点「扫描逾期」标记超期任务  

用 `admin` 登录「校级监管」可对比三院数据，并在预警中心查看逾期督办；支持按学院筛选台账，并导出全校或单院巡视材料包。

议题/会议详情含材料、合规日志、操作记录；会议页另有签到表、请假报备、计票预览与流程步骤条。  
秘书 / 书记 / 院长 / 学院管理员可在侧栏「操作审计」按资源查询本院操作日志（校级可看全校）。

申报时可勾选「临时动议」：系统自动增加动议说明必填材料，且须书记/院长双签后才能入会议程。  
选择不同议题分类（如师资、科研、表彰）会生成对应必填材料清单。  
联席会申报可勾选「党委会前置」并关联已形成的党委决议。

按钮与操作已按角色收敛：副院长等成员默认以参会/表决为主，审题签署仅书记院长可见。

### 工作台与参会名单

- 登录后「工作台」展示个人待办：联席双审、党委审题、纪要签署、督办、待签到、待阅件，可一键跳转处理。
- 工作台同时展示**双会标准流程**与本院进行中事项所处环节（申报→审题→开会→纪要→督办→归档），可按环节筛选。
- 会议秘书 / 学院管理员 / 书记可在「参会名单」维护联席会与党委会正式成员、列席人员（影响法定人数与表决权）。
- **人员管理（校院两级）**：学院管理员/书记维护本院账号、角色、启用禁用、重置密码、删除（有业务数据时禁止删除，请改用禁用）；校级可跨院查询与纠偏，不可由学院分配 `SCHOOL_ADMIN`。
- **系统管理（校级，独立端口 5174）**：与业务端 / 校级监管分开；`admin` 在系统管理端维护学院、全校用户、议题分类字典。有业务数据的学院、已被议题引用的分类禁止删除。
- 「消息中心」接收审题、开会签到、纪要签署、督办等站内提醒（侧栏显示未读数）。
- 议题/会议列表为空时提供「去申报/去创建」引导按钮。

### 请假 / 阅件 / 归档

- **请假报备**：参会人员可在会议详情会前请假；不影响应到基数，已请假不可签到/讨论/表决。
- **阅件回执**：议题材料上传后，参会人员可点「阅件回执」；工作台汇总待阅议题。
- **结束会议**：进行中可由秘书/书记/院长点「结束会议」→ 状态变为「已结束」；关闭签到、讨论、表决与形成决议，仍可起草并签署纪要。
- **会议归档**：纪要生效（联席双签 / 党委书记签）后，秘书可归档；会议列表支持按状态筛选（含已结束/已归档）。

### 催办 / 紧急临机 / 公开

- **督办催办**：办公室/书记/院长可对未办结任务催办，累计次数并推送站内消息。
- **紧急临机处置**：联席会议题可标记「紧急临机」，须上传说明；决议后书记+院长双签补确认（规则第十三条）。
- **决议公开**：形成决议时可标记公开；议题详情可切换公开/内部，涉密不可公开。

### 档案 / 缺席意见 / 重大调整

- **档案中心**：侧栏检索已决议/已归档会议，支持关键词、三重一大、公开、学年筛选；可查看会议全宗（签到/材料/表决/纪要/督办）。
- **缺席书面意见**：未签到正式成员可在会议详情登记书面意见，**不计票**。
- **督办重大调整**：执行中需重大调整时回流生成新议题重新上会，禁止直接改原决议。

### 党委会演示路径

1. 侧栏进入「党委会议题」→ 申报 → 上传材料 → 提交书记审  
2. 用 `secretary` 登录点「书记同意」  
3. 进入「党委会开会」→ 创建会议并勾选已审题议题 → 签到表决 → 决议（可转联席会）  
4. 书记签署纪要生效；也可在议题详情直接「形成决议并转联席会」  
5. 回到「联席会议题」继续双审、上会  

### 校级监管

用 `admin` 登录后，侧栏出现「校级监管」：学院对比、会议台账、转办链路、预警中心（只读报表 / 预警 / 导出）。  
点击「导出巡视材料包」可下载 ZIP（含学院对比/会议台账/督办/合规日志/转办链路/预警/抽样会议全宗）。

### AI 辅助（一期 + 二期演示）

- **材料摘要**：议题详情页「AI 材料摘要」→ 上传材料后生成一页纸辅读（不替代原文与审签）
- **纪要初稿**：会议详情页「AI 生成初稿」→ 建议稿可编辑 →「采纳到正文」→ 秘书保存 → 书记/院长人工签署
- **规则问答**：工作台「议事规则问答」→ 基于〔2021〕20号知识库检索（可叠加大模型综合答复）
- **申报辅助**：联席/党委申报弹窗「根据标题生成建议」→ 推荐分类、材料清单、前置/重大/临时等标记（须人工确认后提交）
- **审题简报**：议题详情审题区「生成审题简报」→ 齐备性检查 + 关注点 + 同类历史（辅读，不可代审）
- **会议智能助理**：业务端右下角浮层 → 汇报待办/进展、规则问答、办理入口；审题/表决仅出确认卡，**不自动提交**（详见 `docs/会议智能助理.md`）

```bash
# 可选：在 backend/.env 配置 OpenAI 兼容接口
LLM_API_KEY=sk-xxx
LLM_BASE_URL=https://api.openai.com/v1
LLM_MODEL=gpt-4o-mini
```

- **未配置密钥**：本地演示生成 / 知识库检索，链路可完整跑通
- **已配置密钥**：调用兼容 `/v1/chat/completions` 的大模型
- 每次生成写入 `AiGeneration` 与操作审计；**不改议题/会议终态，不可自动签署**

## 数据库：SQLite / MySQL

本地开发默认 **SQLite**（`backend/.env` 中 `DATABASE_URL="file:./dev.db"`），e2e 也走 SQLite，无需额外服务。

生产或联调可切到 **MySQL 8**：

```bash
# 1. 启动 MySQL（需本机已安装 Docker）
docker compose up -d

# 2. 切换 Prisma schema + .env
./scripts/switch-db.sh mysql

# 3. 建表并灌演示数据
cd backend
pnpm exec prisma db push
pnpm prisma:seed
```

切回本地 SQLite：

```bash
./scripts/switch-db.sh sqlite
cd backend && pnpm exec prisma migrate dev && pnpm prisma:seed
```

相关文件：

| 文件 | 说明 |
|------|------|
| `docker-compose.yml` | MySQL 8 容器（库名 `qfnu_meeting`，用户 `meeting` / `meeting123`） |
| `backend/.env.mysql.example` | MySQL 连接串示例 |
| `backend/prisma/schema.sqlite.prisma` | SQLite 权威 schema |
| `backend/prisma/schema.mysql.prisma` | MySQL schema（长文本字段为 `@db.Text`） |
| `sql/002_mysql_init.sql` | 由 MySQL schema 生成的建表脚本（可手工导入） |
| `scripts/switch-db.sh` | 一键切换 provider / `DATABASE_URL` / `prisma generate` |

查看当前库类型：`./scripts/switch-db.sh status`

## 已落地的硬规则

- 书记/院长双审不一致 → 暂缓上会  
- 未达半数（重大事项 2/3）→ 禁止形成决议  
- 列席无表决权；缺席意见不计票（数据结构已预留）  
- 赞成票须超过应到会正式成员半数（重大事项为三分之二）  
- 纪要须书记+院长双签后生效  
- 通过类决议自动生成督办任务  
- 临时动议须书记+院长双签（党委会为书记审题）并上传动议说明后方可入会  
- 会前材料按议题分类动态生成必填清单  
- 议题可设置回避名单，回避人员不得讨论/表决  
- 书记/院长须最后表态（其他正式成员发言后方可）  
- 关键节点自动推送站内消息（审题、签到、纪要、督办）  
- 写操作按角色鉴权；代签到仅会务可代签；督办仅责任人/管理员可办结  
- 会前请假不影响应到基数；已请假不得签到/讨论/表决  
- 会前材料支持阅件回执；纪要生效后方可归档  
- 督办支持办公室催办（站内消息 + 次数累计）  
- 紧急临机处置须事后书记院长双签补确认；决议可标记公开/保密  
- 档案中心支持按学年/三重一大/公开检索会议全宗  
- 缺席书面意见不计票；督办重大调整须回流新议题重新上会  
- 人员按校院两级管理：学院维护本院账号与角色，校级跨院监管；禁用账号不可登录
